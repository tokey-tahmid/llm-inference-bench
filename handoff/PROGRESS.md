## What failed

**TP=8 multi-node.** The pinned vLLM image (`0.27.1`, digest recorded in
`provision.lock.json`) does not include Ray. `--distributed-executor-backend
ray` therefore cannot be used, and vLLM's only alternative in-tree backend
(`mp`) is single-node only. Recorded as a real failure in
`docs/notes.md`, not fabricated to fill the axis. The `slurm/run_tp8_ray.sh`
script is committed for a future attempt.

## What a human needs to decide

1. **Should the vLLM container be rebuilt with Ray to close the TP=8 gap?**
   This changes the backend image digest and therefore breaks the "same
   backend as the earlier sweeps" invariant. Trade-off is: one honest TP=8
   data point vs. cross-comparability with everything already measured. If
   yes, rebuild uses a stale `provision.lock.json` as a starting point.
2. **Should the SGLang prefix-cache adapter be updated?** SGLang reports 0
   hit rate at every shared-prefix ratio because the adapter is looking for
   vLLM-style counter names in SGLang's Prometheus output. A short adapter
   patch and a targeted re-run (~1-2 node-hours) would fill in the SGLang
   column of the prefix-caching section. Currently left as a stated
   limitation.
3. **Are the packing-interference deltas at high concurrency (+3553% TTFT,
   -78% throughput at c=128) real limits or measurement pathology?**
   `results/RESULTS.md` prints them as-measured. The pattern (blow-up
   starts at c=8 and gets catastrophic at c=128) is consistent with the
   "host-side bandwidth on the prefill path" mechanism explained in
   `docs/notes.md`, but the specific magnitude at c=128 deserves a
   second-look sweep.
4. **Do we accept the current dirty-git provenance on ~61% of artifacts?**
   The image digest is pinned so replay is possible; the exact code that
   ran is not recoverable from the git SHA alone because the tree was
   modified. Sweeps after 2026-08-31 are clean. Either everything gets
   remeasured on the clean tree (~50-80 node-hours) or the dirty-tree
   artifacts remain as-is with the current caveat.
